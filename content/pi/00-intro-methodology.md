# 第 00 章 · 导读、方法论与旧文档审计

> 这一章先说清楚三件事：本教程写给谁、它和此前几份"研究笔记"有什么**本质区别**、以及你该怎么读。读完后你会明白——为什么上一版让你觉得"在抄"，而这一版不会。

## 学习目标

- 理解本教程的定位：从 0 到 1 学会智能体开发，最终能给自己做一个 DeepSeek 桌面端 Agent
- 看懂本教程与 `deepseek-pi-study` / `kimi-m3-study` / `grok-pi-study` 的关系——以及为什么"像在抄"是错觉也是事实
- 掌握"先跑后读、读真源码、拒绝二手结论"的学习方法

## 一、你手里这份教程是什么

这是一份**以 Pi 真实源码为唯一事实来源**的智能体开发学习文档。Pi 是一个开源编码智能体（coding agent），也是你正在使用的这个 AI 助手的本体，代码量约 25 万行 TypeScript、11 个包。

它和你见过的"AI 科普文章"不同：

- **不编造概念**。每一个术语、每一段机制，都对应 `packages/` 下某个真实文件的真实实现，并标注 `文件:行号`。
- **不堆砌名词**。先建立 AI / 大模型 / 智能体的底层直觉（第 01–12 章通识），再沿真实调用链逐文件拆源码（第 13–42 章），最后落到"你自己写一个 Agent"（第 43–48 章）。
- **为 0 基础但想真懂的人写**。代码块都带语言标签和行号，难点配 `::: tip` 提示框，每章末尾有 `自查清单` 让你自检。

## 二、关于"你是不是在抄"——一份诚实的审计

你之前的直觉部分成立，我必须正面回应。在重写前，我把项目里能找到的几份旧材料都实际读了一遍，结论如下：

|--------|--------------|------|
| `deepseek-pi-study` | **存在**（12 章 / 3769 行） | 一份结构完整的 Pi 学习笔记 |

### 2.2 旧 `deepseek-pi-study` 里被核实出的事实错误

- **版本号错误**：它自称"v0.84.x / 2026-08 版本"。我核对了 `package.json` 根版本字段，Pi 当前 main 分支的真实版本是 **`0.0.3`**（commit `2e4d2395`）。`v0.84.x` 是凭空写出的错误版本号。
- **结构陈旧**：它的章节编排（认知 → 架构 → 运行 → pi-ai → agent-loop → CLI → 会话 → TUI → 扩展 → 实践）是一套合理的"源码导读"框架，但和我上一版 `hy-study` 的 25 章骨架高度同构。
- **结论**：上一版 `hy-study` 不是抄了旧文档的**文字**，而是**复用（甚至照搬）了它的章节骨架**，同时每章只有 ~73 行、像大纲而非详解。这正是你觉得"在抄"的真正根源——不是内容雷同，是结构雷同且深度不够。

### 2.3 这一版怎么做才叫"全新、全量、完善"

- **结构独立**：本章之后是 49 章、七大段，章节编号、标题、划分逻辑全部重新设计，不再镜像任何旧材料。
- **事实来源唯一**：所有机制描述必须回到 `packages/` 真源码，禁止从旧笔记转述。
- **篇幅加倍且深入**：单章 250–400 行起步，要求含真实源码引用、调用链图解、动手练习、自查清单。
- **通识补全**：你明确要的"AI / 大模型 / 智能体拓展知识"单独成段（第 01–12 章），不是几句话带过。

## 四、学习方法：先跑后读，读真源码

1. **先让它跑起来**（第 14 章），再读代码。带着运行中的程序读源码，比干读快十倍。
2. **每章都动手**：改一行代码、加一个工具、打断点看事件流。修改是最好的理解。
3. **带着问题读**：每章开头有"学习目标"，末尾有"自查清单"，用来检验是否真懂。
4. **边读边画图**：agent-loop、消息流转、依赖方向这些核心结构，自己画一遍才算吃透。
5. **怀疑一切二手结论**：包括本教程。任何 `文件:行号` 你都可以打开核实；发现我写错，请直接指出来。

> **提示 · 一个重要的诚实声明**
>
> 本教程引用的行号来自写作时的 main 分支（commit `2e4d2395`，根版本 `0.0.3`）。Pi 在快速演进，行号可能随版本漂移，但**文件结构与核心机制稳定**。若行号对不上，以文件内的函数名 / 导出名为准。
