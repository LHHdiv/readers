# 第 01 章 · AI 简史：从规则系统到生成式大模型

> 这一章不是为了让你背年份。它要回答一个问题：**为什么"能自己调用工具、改你代码"的智能体，偏偏是在 2023 年之后才出现？** 想清楚这条因果链，你才知道 Pi 这类项目在做什么、不在做什么。

## 学习目标

- 用一句话说清符号主义与联结主义的根本分歧
- 理解专家系统为什么强大又为什么崩塌
- 建立"反向传播"的直觉（不需要会算梯度）
- 说清 Seq2Seq → 注意力 → Transformer → GPT 的动机链条
- 知道"生成式"到底生成的是什么
- 判断 Pi 这类编码智能体在整张图谱中的位置

## 一、先给你一条时间线

先看全景，后面每一段都会展开。

```text
1950 ──── 图灵测试：机器能"思考"吗
   │
1956 ──── 达特茅斯会议：AI 作为一门学科诞生
   │
   │      ┌─────────── 符号主义（Symbolic AI）───────────┐
1960s     │ 逻辑推理、搜索、专家系统                     │
1980s     │ MYCIN / XCON 商业成功 → 知识获取瓶颈 → 崩塌  │
   │      └──────────────────────────────────────────────┘
   │
   │      ┌─────────── 联结主义（Connectionism）─────────┐
1958      │ 感知机 Perceptron                            │
1986      │ 反向传播被重新推广                            │
2012      │ AlexNet：深度学习在图像上碾压传统方法         │
   │      └──────────────────────────────────────────────┘
   │
2014 ──── Seq2Seq：一个序列进，一个序列出
2015 ──── Attention：解决"一个向量装不下整句话"
2017 ──── Transformer：把注意力做成主结构，可大规模并行
2018 ──── GPT-1 / BERT：预训练 + 微调成为范式
2020 ──── GPT-3：规模带来"少样本学习"能力
2022 ──── InstructGPT / ChatGPT：对齐让模型"听得懂人话"
2023 ──── 函数调用 + 长上下文 → 智能体（agent）可行
2024+ ─── 推理模型（thinking）、编码智能体大规模落地
   │
 现在 ──── Pi：把上面所有能力接到你的终端和文件系统上
```

> **说明 · 读这条线的正确姿势**
>
> 每一次跃迁的驱动力都不是"某人更聪明了"，而是**上一代方法撞到了具体的墙**。带着"上一步卡在哪"去读，历史就不再是流水账。

## 二、两条路线的根本分歧

### 2.1 符号主义：智能 = 操作符号

符号主义者认为，思维的本质是**对符号进行逻辑操作**。你把知识写成规则，机器按规则推演，就产生了智能。

```text
知识库：  鸟(X) ∧ ¬企鹅(X) → 会飞(X)
事实：    鸟(麻雀), ¬企鹅(麻雀)
推理引擎：→ 会飞(麻雀)
```

这条路线的优点非常突出：

- **可解释**。每一步结论都能追溯到某条规则。
- **精确**。只要规则对，结论就对，不会"大概是"。
- **无需数据**。你只需要专家，不需要一百万条样本。

### 2.2 联结主义：智能 = 大量简单单元的连接

联结主义者认为，智能不来自符号，而来自**神经元之间连接强度的调整**。没有哪一条"规则"存在于某个位置，知识分散在几百万个权重里。

```text
输入 ──▶ [ w1 w2 w3 ... ] ──▶ 加权求和 ──▶ 非线性 ──▶ 输出
              ▲
              └── 靠数据反复调整这些 w
```

它的特点正好相反：**不可解释、不精确、极度依赖数据**——但它能处理规则写不出来的任务，比如"这张图里是不是猫"。

### 2.3 分歧的现代回响

这不是过时的历史。你今天做智能体，仍然天天在这两条路线之间做取舍：

| 场景 | 更适合的路线 | 在 Pi 里的体现 |
| --- | --- | --- |
| 判断这段代码该怎么改 | 联结主义（大模型） | 交给 LLM 生成 |
| 判断路径是否在工作区内 | 符号主义（写死规则） | 工具层的路径校验代码 |
| 生成 commit message | 联结主义 | LLM 输出 |
| 判断是否需要用户确认 | 符号主义 | 权限策略的确定性判断 |

> 一个成熟的智能体绝不是"什么都问模型"。**能用确定性代码解决的，永远不要交给概率模型**。这句话你会在后面的源码章节里反复验证。

## 三、专家系统：辉煌与它撞上的墙

1970–1980 年代，符号主义走到了商业化的顶点，代表产物叫**专家系统**。

- **MYCIN**：诊断血液感染，给出抗生素建议，准确率一度接近人类专家。
- **XCON**：为 DEC 公司配置小型机订单，据称每年省下数千万美元。

它的结构非常清晰：

```text
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  知识库       │───▶│  推理引擎     │───▶│  解释模块     │
│ (IF-THEN 规则)│    │ (前向/后向链) │    │ (为什么这样答) │
└──────────────┘    └──────────────┘    └──────────────┘
        ▲
        │ 人工录入
   领域专家 + 知识工程师
```

然后它撞上了三堵墙：

1. **知识获取瓶颈**。专家自己说不清自己怎么判断的。让一个老医生把直觉写成 IF-THEN，他会告诉你"看多了就知道"。
2. **规则爆炸**。系统到几千条规则后，新增一条可能与旧规则冲突，维护成本指数上升。
3. **脆而不韧**。规则覆盖不到的输入，系统不是"答得差一点"，而是**彻底失效**。

> **注意 · 这个教训今天依然值钱**
>
> 把智能体的行为全部写成 if-else 提示词分支，是在小规模重演专家系统的悲剧。规则会互相打架，你会陷入"改一句提示词，另一个场景就崩"的循环。第 06 章和第 36 章会讲结构化的替代做法。

## 四、机器学习的兴起：让数据来写规则

既然人写不出规则，那就让机器从数据里**学**出规则。这就是机器学习的核心转向。

```text
传统编程：  规则 + 数据 ──▶ 答案
机器学习：  数据 + 答案 ──▶ 规则（模型参数）
```

1990–2010 年代的主力方法：决策树、支持向量机（SVM）、随机森林、逻辑回归。它们在结构化数据上极其有效，今天在风控、推荐等场景仍是主力。

但它们有个共同软肋：**特征工程**。

模型吃的不是原始数据，而是人手工提炼的"特征"。判断垃圾邮件，你得先想好："包含'中奖'一词吗？发件人域名年龄？感叹号数量？"——特征设计得好，模型才好；而设计特征，又回到了"依赖人类专家"的老问题上。

## 五、深度学习与反向传播直觉

深度学习的野心是：**连特征都让机器自己学**。

### 5.1 层次化特征的直觉

以图像为例，多层网络会自发形成这样的分工：

```text
第 1 层  ──▶ 边缘、明暗变化
第 2 层  ──▶ 角点、纹理
第 3 层  ──▶ 眼睛、轮子、耳朵等部件
第 4 层  ──▶ 猫脸、汽车、人脸
```

没有人告诉它"第 3 层要学眼睛"，这是训练过程自己涌现出来的分工。这就是"深度"的价值——**层数带来抽象层级**。

### 5.2 反向传播：不用公式的解释

想象你在浓雾中的山坡上，要走到最低点，但只能看到脚下一小块地。策略很简单：

1. 感受脚下哪个方向最陡峭地向下（这就是"梯度"）；
2. 朝那个方向迈一小步（步长就是"学习率"）；
3. 重复。

神经网络训练就是这件事，只不过：

- "山"是**损失函数**：模型预测和正确答案的差距。
- "位置"是**所有参数的取值**，可能有几千亿个维度。
- "感受坡度"就是**反向传播**：从输出端的误差出发，按链式法则一层层往回算，得出每个参数该往哪调、调多少。

```text
前向：  输入 ─▶ 层1 ─▶ 层2 ─▶ 层3 ─▶ 预测
                                      │
                                   与答案比较 → 损失
                                      │
反向：  层1 ◀─ 层2 ◀─ 层3 ◀────────────┘
        （每层都得到"我该怎么改"的信号）
```

> **提示 · 为什么这件事等到 2012 年才爆发**
>
> 反向传播 1980 年代就有了。真正让它起飞的是三个条件同时到位：**GPU 提供的算力**、**ImageNet 这类大规模标注数据**、以及 ReLU / Dropout 等让深层网络训得动的工程技巧。**算法、算力、数据缺一不可**——这个三元组在后面每一次跃迁中都会重现。

## 六、Seq2Seq 与注意力：语言任务的转折

图像搞定了，语言难在哪？难在**语言是变长的序列，而且顺序有意义**。

### 6.1 Seq2Seq：编码器—解码器

2014 年的思路很朴素：用一个 RNN 把整句话读完，压成一个固定长度的向量（"语义"），再用另一个 RNN 从这个向量生成目标语言。

```text
我  爱  编  程
│   │   │   │
▼   ▼   ▼   ▼
[RNN 编码器] ──▶ 【一个固定向量 c】──▶ [RNN 解码器] ──▶ I love coding
```

### 6.2 瓶颈非常直白

- 一句 50 个词的话，和一句 3 个词的话，被压进**同样大小**的向量里。长句必然丢信息。
- RNN 必须**一步一步**算，第 t 步依赖第 t-1 步，无法并行，训练极慢。
- 距离越远，梯度传播越困难，长距离依赖学不好。

### 6.3 注意力：别压成一个向量，让解码器回头看

2015 年的注意力机制换了个思路：**保留编码器每一步的输出，解码时按需加权取用**。

```text
编码器输出：  h1    h2    h3    h4
              我    爱    编    程
                     ╲    │    ╱
生成 "coding" 时权重： 0.05 0.45 0.45   ← 主要看"编""程"
生成 "love"   时权重： 0.10 0.80 0.05   ← 主要看"爱"
```

翻译质量立刻提升，而且**权重可视化后是可解释的**——模型确实在"对齐"源词和目标词。

### 6.4 Transformer：把注意力变成主角

2017 年的论文标题就是结论：《Attention Is All You Need》。既然注意力这么好用，为什么还要 RNN？直接去掉循环结构，全部用注意力搭建。

带来的最大红利不是精度，而是**并行**：RNN 必须按时间步串行，而注意力可以让序列里所有位置**同时**参与计算。这意味着能用满 GPU，也就意味着**模型可以做到前所未有的大**。第 02 章会专门拆解它。

## 七、GPT 范式：「生成式」到底生成什么

### 7.1 一个朴素到离谱的训练目标

GPT 的训练任务只有一句话：**给定前面的所有 token，预测下一个 token**。

```text
输入： "今天天气真"
目标： "好"

输入： "function add(a, b) { return a +"
目标： " b"
```

就这么简单。没有语法标注，没有人工标签，任何一段文本天然自带答案（下一个词就在那儿）。这叫**自监督学习**，它让训练数据从"人工标注的几十万条"变成"整个互联网"。

### 7.2 为什么这能产生智能

关键洞察是：**要把下一个词预测得足够准，模型被迫学会一切**。

- 想接对 "法国的首都是____"，必须记住事实。
- 想接对 "2 + 3 = ____"，必须学会算术。
- 想接对 "以下代码的 bug 在于____"，必须理解程序语义。
- 想接对一段对话的回复，必须建模对方意图。

预测下一个 token 是**手段**，压缩世界规律是**结果**。

### 7.3 "生成式"的准确含义

生成式（Generative）指的是：模型输出的是**一个概率分布**，然后从中采样，而不是从固定选项里挑一个。

```text
输入 "今天天气真"
      ↓
模型输出概率分布：
      好    : 0.42
      不错  : 0.18
      糟糕  : 0.09
      冷    : 0.07
      ...（词表里剩下十几万个 token 分掉剩余概率）
      ↓
按 temperature 采样 → "好"
      ↓
把 "好" 拼回输入，重复上面的过程
```

这解释了两个你一定会遇到的现象：

- **同样的问题，两次回答不一样**。因为是采样，不是查表。
- **模型会一本正经地编造**。它优化的是"像不像真的"，不是"是不是真的"。第 03 章会讲对齐如何缓解这一点。

### 7.4 规模带来的质变

GPT-3（2020）证明了一件反直觉的事：把模型和数据一起放大，会**涌现**出小模型完全不具备的能力，其中最关键的是**上下文学习（in-context learning）**——不改一个参数，只在提示词里给几个例子，模型就能照做。

这正是"提示词工程"这门手艺存在的前提（第 06 章）。

## 八、为什么智能体在 2023 年之后才爆发

一个能自己干活的智能体，需要四块拼图**同时**到位。缺任何一块，它都只是个聊天框。

```text
拼图 1：足够强的基础推理
        └─ 能把"重构这个模块"拆成可执行步骤

拼图 2：稳定的结构化输出（函数调用 / tool use）
        └─ 模型不再输出散文，而是输出机器能解析的调用意图
        └─ 这是 2023 年才被产品化的能力

拼图 3：足够长的上下文窗口
        └─ 8K 只能聊天；128K+ 才装得下多个文件 + 长对话历史

拼图 4：可靠的执行环境（工具 + 权限 + 反馈回路）
        └─ 读写文件、执行命令、把结果喂回模型
```

四块齐了，智能体的基本循环才成立：

```text
┌──────────────────────────────────────────────┐
│                                              │
│   用户目标                                    │
│      │                                       │
│      ▼                                       │
│   [ LLM 思考 ] ──▶ 决定：回答？还是调用工具？  │
│      ▲                     │                 │
│      │                     ▼                 │
│      │              [ 执行工具 ]              │
│      │                     │                 │
│      └──── 结果回填上下文 ◀──┘                │
│                                              │
└──────────────────────────────────────────────┘
        循环，直到模型认为任务完成
```

这个循环就是全书的主线。在 Pi 里，它落在 `packages/agent/src/agent-loop.ts`，第 25 章会逐行拆。

> **提示 · 智能体不是新概念，能力才是新的**
>
> "感知—决策—行动"的智能体框架在 AI 教科书里躺了几十年。变的不是框架，是**决策模块终于强到能处理开放世界的任务**。所以别把智能体想得很玄——它就是一个 while 循环加一个足够聪明的决策器。

## 九、Pi 在这张图谱里的位置

把上面的历史收束到具体项目上。Pi 是一个**编码智能体（coding agent）**：以大模型为决策核心，以你的代码仓库为工作场地，以文件读写和命令执行为行动手段。

它在整个技术栈中的位置：

```text
┌─────────────────────────────────────────────┐
│  基础模型层（别人做的）                       │
│  GPT / Claude / DeepSeek / Gemini ...        │
└───────────────────┬─────────────────────────┘
                    │ HTTP + SSE 流式协议
┌───────────────────▼─────────────────────────┐
│  packages/ai   ── 统一多家模型的差异          │
│  消息类型、流式事件、Provider 适配             │
└───────────────────┬─────────────────────────┘
                    │
┌───────────────────▼─────────────────────────┐
│  packages/agent ── 智能体运行时               │
│  agent-loop、工具执行、上下文管理、持久化      │
└───────────────────┬─────────────────────────┘
                    │
┌───────────────────▼─────────────────────────┐
│  packages/coding-agent ── 产品主程序          │
│  CLI、会话、系统提示词、扩展与技能             │
└─────────────────────────────────────────────┘
```

> 依赖方向严格单向：`ai → agent → coding-agent`。下层永远不知道上层的存在。这条约束贯穿整个仓库，也是你日后设计自己智能体时最值得抄的一条。

Pi 当前根版本为 `0.0.3`（写作时 main 约在 commit `2e4d2395`）。版本号小，不代表工程简单——它的复杂度全在"如何把上面这条历史链条稳定地跑在真实机器上"。

## 十、一份历史给你的三条实用结论

1. **能力边界来自训练目标**。模型的本职是预测下一个 token，一切"智能"都是这个目标的副产品。因此它擅长模式补全，不擅长精确计算和事实核验——所以要给它工具。
2. **确定性问题用确定性方案**。专家系统的教训不是"规则没用"，而是"别用规则去做规则不擅长的事"。反过来也成立。
3. **架构的价值在于隔离变化**。模型三个月换一代，但"消息—工具—循环"这套结构很稳。Pi 把易变的（Provider 差异）关在 `packages/ai` 里，就是这个思路。
