# 第 13 章 · 教育智能体专有范式

> 目标：DeepTutor 不是又一个聊天机器人，它是**教育**智能体。这一章讲它区别于通用助手的三张王牌：**标签驱动循环（过程可视化）**、**三层长期记忆（个性化）**、**掌握度学习（真的教会你）**。读完你能说出"教育场景到底逼出了哪些通用场景没有的设计"。

黑话先定义：**范式（paradigm）** 指"一种被验证过的、可以反复套用的设计模式组合"。**标签驱动（label-driven）** 是 DeepTutor 循环的核心玩法——模型每次输出先声明自己在干哪类事；**三层记忆（L1/L2/L3）** 是把"记什么、怎么沉淀、怎么用"分层；**掌握度（mastery）** 是"不满足于答对，而是确认你真的掌握了"的学习指标。

---

## 13.1 教育场景的四个特殊要求

普通助手（问答、写代码、查资料）和辅导老师（DeepTutor 的定位）要求不同：

| 通用助手 | 教育智能体 |
|---------|-----------|
| 给个答案就行 | 答案要**讲清楚过程**，学生要学方法 |
| 记住最近几句 | 记住这个学生**长期**的薄弱点、偏好 |
| 答完即止 | 要**确认掌握**，没掌握就换法子再教 |
| 输出好看即可 | 过程要**可视化**，学生/家长看得见 AI 在想什么 |

这四个要求，逐一逼出了 DeepTutor 的三个核心设计。

## 13.2 王牌一：标签驱动循环（过程可视化）

### 13.2.1 为什么教育场景特别需要"过程"

通用助手可以"闷头算完给结果"。但老师不行——学生需要看到"你为什么这么想、中间调了什么工具、检索了什么资料"。DeepTutor 用**强制模型先吐 LABEL** 的方式把过程变成可观察的状态机：

- `deeptutor/core/agentic/labels.py:17` 定义了 `LABEL_UNKNOWN = "UNKNOWN"`（协议失败的兜底值）；
- `labels.py:34` 的 `classify_label` 负责从模型输出开头识别标签；
- `loop.py:40` 的 `LabelProtocol` 定义了哪些标签合法、哪个算结束。

```text
学生看到的前端卡片（标签驱动的成果）:

  用户提问: "帮我讲讲勾股定理的证明"

  [思考中...]  THINK   ← 模型先吐 THINK，前端显示"思考卡片"
  [检索教材]  TOOL    ← 模型要调 RAG 工具，前端显示"工具卡片"
  [讲解中...] THINK
  [讲解完成]  FINISH  ← 命中终止标签，前端显示"最终答案"
```

每个标签对应一种 UI 状态——这就是"过程可视化"。通用助手不强制标签也能用，但教育场景**要求透明**，所以 DeepTutor 把标签做成了硬协议（详见第 18 章）。

### 13.2.2 标签驱动 vs stopReason 驱动

很多通用智能体（如 OpenAI 的 agent SDK）靠模型返回的 `stop_reason`（工具调用 / 结束）驱动循环。DeepTutor 选择了**更强的标签协议**：

| 维度 | stopReason 驱动 | 标签驱动（DeepTutor） |
|------|----------------|---------------------|
| 状态粒度 | 粗：tool_call / stop | 细：THINK / TOOL / FINISH / 中间标签 |
| 过程可见 | 前端难分清"在思考还是在干活" | 每个标签一种状态，天然可可视化 |
| 错误处理 | 依赖 SDK 内部 | 协议违规可**修复重来**（loop.py:375 `_protocol_violation`） |
| 教育适配 | 一般 | 过程透明，正是教育要的 |

> **提示 · 一句话理解**
>
> 标签驱动 ≈ "模型每走一步先喊一声自己在干嘛"。它不增加智能，但让教育场景最看重的**透明度**成为可能。

## 13.3 王牌二：三层长期记忆（L1/L2/L3）

### 13.3.1 通用助手记不住，教育必须记住

通用助手的对话历史出了会话就没了。但老师必须记住：这个学生上周哪里卡壳了、他喜欢例子还是公式、他怕立体几何。DeepTutor 把"记忆"做成三层，代码在 `deeptutor/services/memory/`：

```text
三层记忆全景（目录 services/memory/）:

  L1 痕迹 trace.py
       │  记录"原始事件": 每次问答、纠错、检索的原始轨迹
       │  （量大、零散、保留全貌）
       ▼
  L2 摘要 consolidator/
       │  定期把 L1 合并成"表面摘要": 这个学生最近在学什么、
       │  反复错哪类题（量大减、可读）
       ▼
  L3 综合快照 snapshot/
       │  沉淀四份"身份文档": recent / profile / scope / preferences
       │  （量极小、每次对话注入、决定个性化）
```

- **L1 痕迹**（`trace.py`）：记录"发生了什么"，保真但零散；
- **L2 摘要**（`consolidator/`）：把零散痕迹总结成可读摘要，解决"太多记不全"；
- **L3 快照**（`snapshot/`）：最终沉淀出四份文档（近期状态、学生画像、学习范围、偏好），**每次对话开始注入上下文**，让模型"记得你是谁"。

这四份 L3 文档就是"个性化"的直接来源——第 26 章会逐文件拆解。

> **说明 · 对比**
>
> 很多通用 coding agent（如 Pi）**没有内置长期记忆**，靠会话文件；DeepTutor 专门为"长期辅导同一个学生"设计了 L1→L2→L3 的沉淀链路。这是教育场景逼出来的典型设计。

### 13.3.2 记忆怎么"用"起来

L3 快照不是存着好看，而是**注入**到每次对话的上下文里（第 30 章"会话沙箱"会讲注入点）。模型看到"这个学生偏好图解、立体几何薄弱"，讲解时就会自动调整——这就是学生感觉"AI 懂我"的技术来源。

## 13.4 王牌三：掌握度学习（Mastery Learning）

### 13.4.1 答对 ≠ 掌握

教育心理学里有个概念：**掌握度学习**——不满足于"学生答对一道题"，而是追踪"他是否真的掌握了这个知识点"，没掌握就换方式再教。DeepTutor 把这件事变成了代码，在 `deeptutor/learning/`：

```text
掌握度学习闭环:

  出题 → 学生作答 → grade_answer 批改(grading.py:13)
                        │ 对 → 记录正确
                        │ 错 → classify_error 分类错误(grading.py:52)
                        ▼
                 compute_mastery 更新掌握度(mastery.py:24)
                        │
                        ▼
                 掌握度低 → 换策略/换题型再教（policy.py / scheduler.py）
                 掌握度高 → 进入下一知识点
```

- `grading.py`：怎么判对错，错了归哪类错因；
- `mastery.py`：把多次对错聚合成一个分数（如正确率加权的滑动估计）；
- `policy.py` + `scheduler.py`：根据掌握度决定**下一步教什么**（第 38 章细讲）。

> **提示 · 为什么这是"专有范式"**
>
> 通用智能体做完题就完事；DeepTutor 把"教学决策"也数据化了——**批改→归因→掌握度→调度** 形成闭环，像个真正的老师。这是教育产品区别于通用助手的本质。

## 13.5 三张王牌怎么协同

```text
一次"辅导会话"如何同时用到三张王牌:

  学生进来
    │
    ├─ L3 快照注入(13.3)  → 模型知道"你是谁、你薄弱在哪"
    ▼
  提问 → 标签驱动循环(13.2) → THINK/TOOL/FINISH 全程可视化
    │
    ├─ 讲解中调 RAG 检索教材（TOOL 阶段）
    ▼
  出题练习
    │
    ├─ grade_answer + compute_mastery(13.4) → 更新掌握度
    │
    ├─ 掌握度低 → policy/scheduler 决定下一轮讲什么
    ▼
  会话结束 → 本轮轨迹进 L1 → 后续合并进 L2 → 沉淀 L3
```

过程可见（王牌一）+ 记得住人（王牌二）+ 确认学会（王牌三）——三者合起来，才配叫"教育智能体"。
