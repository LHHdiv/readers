# 第 01 章 · AI 简史与生成式大模型

> 目标：用大白话讲清楚"人工智能"这七十年到底发生了什么，为什么最后走到了"大模型"这一步，以及 DeepTutor 里那个会跟你聊天的东西，本质上到底在做什么运算。读完这章，你听到 LLM、预训练、生成式、Transformer 这些词时，脑子里能有画面，而不是一片空白。

## 1.1 先给你一个坐标系

学任何东西，最怕的是"零散知识点砸脸"。所以我们先把整条时间线摆出来，后面每一节都是往这条线上挂肉。

```text
1950s ──────► 1980s ──────► 2010s ──────► 2017 ──────► 2020s ──────► 现在
 规则系统        机器学习        深度学习      Transformer   生成式大模型     智能体
   │              │              │             │             │            │
"人写规则"    "人给例子,       "机器自己       "让每个词      "把整个互联    "模型不只
 机器执行      机器找规律"      找特征"        互相看"        网读一遍"      说话,还
                                                                           会干活"
```

一句话概括这条线的主旋律：**人类干的活越来越少，机器自己学的越来越多。**

- 规则系统：规则是人写的，特征是人定的，答案是人算的。
- 机器学习：规则是机器学的，但"看哪些特征"还是人定的。
- 深度学习：连"看哪些特征"都让机器自己学。
- 大模型：连"学什么任务"都不用提前定，先把语言本身学会，任务是后来才说的。
- 智能体：模型不再只输出文字，它能调用工具、读文件、改代码、查资料——这就是 DeepTutor 所在的层。

> **说明 · 本章不需要你懂数学**
>
> 下面会出现"参数""向量""梯度"这类词。你**不需要**会算它们。你只需要建立一个直觉：所有这些技术，做的都是同一件事——**从大量例子中，找出输入和输出之间的对应关系**。数学只是找这个关系的工具，就像扳手只是拧螺丝的工具。

## 1.2 第一阶段：规则系统（1950s–1980s）

### 1.2.1 专家系统长什么样

最早的 AI 想法非常朴素：既然人类专家能看病，那我们就把专家脑子里的规则全部写下来，让计算机照着执行，不就有一个电子医生了吗？

这类系统叫**专家系统（Expert System）**。它的核心是一大堆 `如果……那么……` 的规则：

```text
如果 (体温 > 38.5) 并且 (咳嗽 = 真) 并且 (喉咙痛 = 真)
那么 → 可能是流感 (置信度 0.7)

如果 (体温 > 38.5) 并且 (皮疹 = 真)
那么 → 可能是麻疹 (置信度 0.6)
```

1970 年代的 MYCIN 系统就是这么诊断血液感染的，规则有几百条，效果一度接近初级医生。当时人们非常乐观。

### 1.2.2 为什么撞墙

问题在**规则爆炸**。

现实世界的判断条件是组合爆炸的。三个症状你能写规则，三十个症状的所有组合是十亿量级，人类专家写不完，也说不清。更糟的是，人类专家自己也讲不明白自己是怎么判断的——医生看一眼病人"觉得不对劲"，这个"觉得"你怎么写成 `如果……那么……`？

这个现象有个专门的名字，叫**波兰尼悖论（Polanyi's Paradox）**：*我们知道的，比我们能说出来的多。*

> 规则系统的死穴不是速度不够快，而是**人类无法把自己的直觉完整地写成规则**。这一点非常关键——后面所有技术，本质上都是在绕开这个死穴。

于是 AI 迎来了第一次"寒冬"，投资撤离，实验室关门。

## 1.3 第二阶段：机器学习（1990s–2010）

### 1.3.1 从"写规则"到"喂例子"

既然人写不出规则，那换个思路：**我不告诉你规则，我给你一万个例子，你自己去找规律。**

这就是**机器学习（Machine Learning, ML）**。

举个最直观的例子——判断一封邮件是不是垃圾邮件：

```text
规则系统的做法：
  程序员写：如果标题包含"中奖"→ 垃圾邮件
  → 垃圾邮件发送者改成"中 奖"，规则失效，程序员再改规则，无限循环

机器学习的做法：
  人类给：10000 封已经标好"垃圾/正常"的邮件
  机器算：统计哪些词在垃圾邮件里出现得特别频繁
  机器出：一个打分函数，新邮件进来打个分,超过阈值就判垃圾
```

注意这里的关键变化：**人类的工作从"写规则"变成了"准备带标签的例子"**。这些带标签的例子叫**训练数据（training data）**，让机器从中找规律的过程叫**训练（training）**。

### 1.3.2 特征工程：人类还在出力

但机器学习时代，人类还有一件苦差事没被解放，叫**特征工程（Feature Engineering）**。

机器不能直接"看"一封邮件，你得先把邮件变成一串数字。变成哪些数字，是人决定的：

| 人工设计的特征 | 这封邮件的取值 |
| --- | --- |
| 是否包含"免费" | 1 |
| 感叹号个数 | 7 |
| 全大写单词比例 | 0.34 |
| 发件人是否在通讯录 | 0 |
| 正文长度 | 128 |

这一行数字叫**特征向量（feature vector）**。选哪些特征，直接决定模型好不好用。当年一个机器学习工程师 80% 的时间都花在"想特征"上。

问题又来了：**图像怎么办？** 一张猫的照片，你要设计什么特征？"有没有胡须"？胡须在图里是哪几个像素？人类根本说不清。

于是人们又卡住了。

## 1.4 第三阶段：深度学习（2012–2017）

### 1.4.1 神经网络直觉

**神经网络（Neural Network）** 这个名字听起来很玄，其实它就是一个**多层的数字变换管道**。

想象一个工厂流水线：

```text
输入层            隐藏层 1          隐藏层 2         输出层
(原始像素)       (边缘/线条)      (眼睛/耳朵)      (是不是猫)

[0.2]  ──┐
[0.8]  ──┼──►  [边缘检测]  ──┬──►  [找到眼睛]  ──┐
[0.1]  ──┤                   │                    ├──► [0.93 是猫]
[0.5]  ──┼──►  [角点检测]  ──┼──►  [找到耳朵]  ──┤
[0.9]  ──┘                   │                    │
  ...                        └──►  [找到毛纹]  ──┘

每一层做的事:  把上一层的数字,乘上一堆权重,加起来,再压缩一下
```

每两层之间那"一堆权重"就是**参数（parameters）**。训练，就是不停微调这些参数，让最后输出的答案越来越接近正确答案。调参数的方法叫**梯度下降（gradient descent）**，你可以理解成"在山谷里蒙眼下山，每次朝最陡的下坡方向挪一小步"。

> **提示 · 参数量到底意味着什么**
>
> 你常听到"这个模型有 700 亿参数"。700 亿就是上面那些权重数字的总个数。参数越多，模型能记住和拟合的模式越复杂，但也越贵、越慢。这就像一个人的词汇量——词汇量大不等于聪明，但词汇量太小一定表达不了复杂想法。

### 1.4.2 表示学习：特征让机器自己找

深度学习最革命性的地方，是它**干掉了特征工程**。

你不用再告诉机器"看胡须"。你只要把原始像素丢进去，网络的浅层会自己学会检测边缘，中层自己学会检测眼睛耳朵，深层自己学会"这是一只猫"。这个能力叫**表示学习（Representation Learning）**。

2012 年 AlexNet 在 ImageNet 图像识别比赛上大幅甩开所有传统方法，深度学习正式引爆。

### 1.4.3 RNN 与它的天花板

图像搞定了，那**语言**呢？

语言有个麻烦特性：**它是有顺序的，而且长度不固定**。"狗咬人"和"人咬狗"，词一样，意思天差地别。

早期的方案叫 **RNN（循环神经网络）**：从左到右一个词一个词读，每读一个词就更新一下"记忆状态"。

```text
RNN 读句子: "我 昨天 在 图书馆 借 了 一 本 书"

 "我" ──► [记忆] ──► "昨天" ──► [记忆] ──► "在" ──► [记忆] ──► ... ──► "书"
           │                     │                    │
        只记得"我"           记得"我昨天"        记得"我昨天在"
```

RNN 有两个致命伤：

1. **健忘**。读到第 50 个词时，第 1 个词的信息已经被反复覆盖，基本忘光了。这叫**长距离依赖问题**。
2. **不能并行**。必须读完第 1 个词才能读第 2 个，天生串行，GPU 的并行算力用不上，训练慢到无法扩大规模。

这两个问题，卡住了整个自然语言处理领域将近十年。

## 1.5 第四阶段：Transformer（2017）

2017 年，Google 的论文 *Attention Is All You Need* 提出了 **Transformer** 架构，一次性解决了上面两个问题。

它的核心思路简单到有点粗暴：**别一个一个顺序读了，把整句话同时摊开，让每个词直接看到其他所有词。**

```text
RNN (串行,健忘):
  我 → 昨天 → 在 → 图书馆 → 借 → 书      读到"书"时快忘了"我"

Transformer (并行,全连接):
      我 ←──────────────────┐
      昨天 ←────────────┐   │
      在 ←──────────┐   │   │
      图书馆 ←──┐   │   │   │
      借 ←──┐   │   │   │   │
      书 ───┴───┴───┴───┴───┘   "书"一步就能看到"我"和"图书馆"
```

这个"每个词看其他所有词"的机制，叫**自注意力（Self-Attention）**。它是整个大模型时代的地基，重要到我们要用**整个第 2 章**来单独讲它。

Transformer 带来的直接后果是：**可以并行训练了，于是可以把模型做得非常大**。规模一大，就出现了让所有人吃惊的现象——**涌现（emergence）**：模型大到一定程度，突然会做一些从没专门教过它的事，比如写代码、做推理、翻译小语种。

## 1.6 判别式 vs 生成式：一个必须掰清楚的区分

这是初学者最容易糊涂的一对概念，我们用一张表和一个例子讲透。

| 维度 | 判别式模型（Discriminative） | 生成式模型（Generative） |
| --- | --- | --- |
| 它回答什么问题 | "这个东西**是哪一类**？" | "下一个东西**应该是什么**？" |
| 输出形态 | 一个标签 / 一个分数 | 一段全新的内容 |
| 典型任务 | 垃圾邮件分类、人脸识别、情感判断 | 写文章、画图、生成代码 |
| 直觉类比 | 考试里的**选择题**（从给定选项挑） | 考试里的**作文题**（从零写出来） |
| 代表模型 | BERT、ResNet、逻辑回归 | GPT、Claude、Stable Diffusion |

用同一句话举例：

```text
输入: "这家餐厅的菜简直难以下咽"

判别式模型输出:  情感 = 负面 (置信度 0.96)
                 ↑ 从"正面/负面/中性"三个已知选项里挑一个

生成式模型输出:  "看来你这次用餐体验很糟糕。方便说说是味道
                  的问题,还是服务的问题吗?我可以帮你写一份
                  投诉建议。"
                 ↑ 凭空造出一段之前不存在的文字
```

**大语言模型（LLM）本质上是生成式的**。它做的唯一一件事就是：给定前面的文字，生成后面的文字。所有你看到的能力——回答问题、写代码、当老师——都是这一件事的包装。

## 1.7 预训练模型是什么

现在讲一个特别关键、但很多人从没被讲清楚的概念：**预训练（Pre-training）**。

### 1.7.1 老办法的浪费

深度学习早期，每做一个新任务就要从零训练一个新模型：

```text
做情感分析 → 收集 10 万条标注数据 → 从零训练模型 A
做机器翻译 → 收集 100 万条对照句 → 从零训练模型 B
做问答系统 → 收集 50 万条问答对 → 从零训练模型 C

三个模型互不相通,三份标注成本,三次从零开始
```

这非常浪费。就像每教一个学生学一门专业课，都要先教他从头认字一样荒谬。

### 1.7.2 预训练的思路

聪明的做法是**两步走**：

```text
第一步 预训练 (Pre-training) —— 只做一次,极贵
  ┌────────────────────────────────────────────┐
  │ 把整个互联网的文本(书/网页/代码/论文)倒进去 │
  │ 任务只有一个: 遮住一个词,猜它是什么         │
  │ 不需要任何人工标注 —— 文本自己就是答案      │
  │ 花费: 几千万美元, 几万张 GPU, 数月          │
  └────────────────────────────────────────────┘
                      ↓
          得到一个"通识很强"的基座模型
                      ↓
第二步 适配 (Adaptation) —— 做很多次,很便宜
  ┌──────────────┬──────────────┬──────────────┐
  │ 微调成客服   │ 微调成医生    │ 只写提示词    │
  │ 几千条数据   │ 几千条数据    │ 零训练数据    │
  └──────────────┴──────────────┴──────────────┘
```

**预训练模型 = 上过通识教育、但还没入职培训的毕业生。** 它读过海量的书，语言能力、常识、逻辑都在，只是还不知道你公司的具体规矩。

这个"读海量文本学语言"的过程为什么不需要标注？因为**文本自己就是标准答案**：把 "今天天气真___" 的最后一个词遮住，正确答案 "好" 就在原文里躺着。这种自己给自己出题的方式叫**自监督学习（Self-Supervised Learning）**，它是大模型能吃下整个互联网的根本原因。

第 3 章会详细讲第二步"适配"里的监督微调和 RLHF。

## 1.8 LLM 的本质：预测下一个词

现在我们可以回答那个最根本的问题了：**ChatGPT 到底在干什么？**

答案朴素到令人失望：**它在做超级加强版的输入法自动补全。**

### 1.8.1 手机输入法的类比

你在手机上打"今天天气真"，输入法会弹出候选："好"、"不错"、"糟"。它是怎么知道的？统计——在它见过的语料里，"今天天气真"后面跟"好"的次数最多。

LLM 做的是同一件事，只是：

- 输入法看前 2–3 个词，LLM 看前面**几万个词**；
- 输入法用简单统计，LLM 用**几千亿参数的神经网络**；
- 输入法只补一个词，LLM 把补出的词**接回输入，再补下一个**，循环上千次。

### 1.8.2 一次生成的完整过程

```text
你输入: "解释一下什么是递归"

第 1 轮: [解释一下什么是递归]              → 预测下一个词 → "递"
第 2 轮: [解释一下什么是递归 递]           → 预测下一个词 → "归"
第 3 轮: [解释一下什么是递归 递归]         → 预测下一个词 → "就"
第 4 轮: [解释一下什么是递归 递归就]       → 预测下一个词 → "是"
  ...
第 N 轮: [......一个函数调用它自己]        → 预测下一个词 → <结束>

每一轮:
   完整上下文 ──► 神经网络 ──► 词表里每个词的概率
                                 "递" 0.31
                                 "它" 0.12
                                 "简" 0.09    ──► 按概率抽一个
                                 ...
```

这个"把输出接回输入再算一次"的模式叫**自回归（autoregressive）**。它解释了三件你一定遇到过的事：

1. **为什么回答是一个字一个字蹦出来的？** 因为它真的是一个一个算出来的，这也是"流式输出"的物理原因（第 11 章细讲）。
2. **为什么同样的问题两次答案不一样？** 因为最后一步是**按概率抽样**，不是取最大值。这个抽样的随机程度由 `temperature` 参数控制。
3. **为什么它会一本正经地胡说八道（幻觉）？** 因为它的目标从来不是"说真话"，而是"生成看起来最合理的下一个词"。合理和真实，是两件事。

> **注意 · 关于"它到底懂不懂"**
>
> "预测下一个词"听起来很低级，于是很多人下结论说"LLM 只是随机鹦鹉，什么都不懂"。这个判断下得太快了。要在海量文本上把下一个词预测准，模型被迫学会语法、事实、逻辑关系甚至一定的推理链条——因为不学会这些，就预测不准。目前学界对"这算不算理解"没有共识。作为开发者，你更该关心的是**它在什么情况下可靠、什么情况下不可靠**，而不是给它贴哲学标签。

## 1.9 GPT 系列：一条"变大 + 变听话"的路

| 时间 | 模型 | 关键变化 | 对开发者的意义 |
| --- | --- | --- | --- |
| 2018 | GPT-1 | 证明"预训练 + 微调"路线可行 | 学术验证 |
| 2019 | GPT-2 | 参数放大到 15 亿，零样本能力初现 | 发现"不微调也能干活" |
| 2020 | GPT-3 | 1750 亿参数，**上下文学习**出现 | 只写提示词就能用，API 时代开启 |
| 2022 | InstructGPT / ChatGPT | 引入 **RLHF**，从"会续写"变成"会对话" | 普通人能用了 |
| 2023+ | GPT-4 类 | 多模态、超长上下文、可靠函数调用 | 智能体成为可能 |
| 2024+ | o1 / R1 类 | **推理模型**，答前先长思考 | 复杂任务准确率跃升（第 4 章） |

这里要特别点出 GPT-3 带来的 **上下文学习（In-Context Learning）**：你不需要重新训练模型，只要在提示词里给它几个例子，它当场就学会了新任务。

```text
提示词里直接写:

  把下面的话翻译成海盗腔:
  正常: 你好朋友        海盗: 嗬,伙计!
  正常: 天气不错        海盗: 今日风向甚佳!
  正常: 我饿了          海盗: ???      ← 模型自己补出海盗腔

模型的参数一个都没变,但它"学会"了这个任务
```

这件事的意义怎么强调都不过分：**它让"用 AI"从"训练模型"变成了"写好提示词"，把门槛从博士降到了会写字。** 整个提示工程、智能体、DeepTutor 这类产品，都建立在这个能力之上。

## 1.10 从"会说话"到"会做事"：智能体

到这一步，模型已经很能说了，但它有三个硬伤：

1. **不知道新事**——训练数据有截止日期，问它今天的新闻它不知道。
2. **不会算数**——它是在"猜"数字的样子，不是在计算。
3. **改变不了世界**——它只能吐字，不能真的帮你把文件存到硬盘上。

解决办法是给它装上"手脚"：允许它在生成过程中**调用工具**——搜索、执行代码、读写文件、查数据库。模型负责决定"什么时候用哪个工具、传什么参数"，程序负责真正执行，并把结果塞回上下文让模型继续。

这就是**智能体（Agent）**。

```text
        ┌──────────────────────────────────┐
        │            循环 (Loop)            │
        │                                  │
   用户 ──► 大模型思考 ──► 要用工具吗?      │
        │       ▲              │           │
        │       │         是   │   否      │
        │       │              ▼    ▼      │
        │       │        [执行工具] [输出答案] ──► 用户
        │       │              │
        │       └── 结果塞回 ◄─┘
        └──────────────────────────────────┘
```

**这个循环，就是 DeepTutor 的心脏。** 在源码里它叫"标签驱动循环（label-driven loop）"，入口是 `deeptutor/core/agentic/loop.py:173` 的 `run_agentic_loop`。第 18 章会把它一行一行拆开讲，现在你只要认得这张图就够了。

## 1.11 DeepTutor 站在这条脉络的哪一段

把整章的脉络收束到我们要学的这个项目上：

```text
      预训练大模型 (别人训练好的,DeepTutor 不训练模型)
              │
              │  通过 API 调用
              ▼
   ┌─────────────────────────────────────────┐
   │  DeepTutor                              │
   │                                         │
   │  服务层  deeptutor/services/llm/        │ ← 对接各家模型
   │            factory.py 造客户端           │
   │            cloud_provider.py  云端       │
   │            local_provider.py  本地       │
   │                                         │
   │  引擎层  deeptutor/core/agentic/loop.py │ ← 智能体循环
   │            :40  LabelProtocol           │
   │            :173 run_agentic_loop        │
   │                                         │
   │  上下文  deeptutor/core/context.py:34   │ ← UnifiedContext
   │            一次对话需要的所有材料         │
   │                                         │
   │  编排层  deeptutor/runtime/             │
   │            orchestrator.py:26           │ ← ChatOrchestrator
   └─────────────────────────────────────────┘
```

三个要点，帮你摆正预期：

- **DeepTutor 不训练模型**。它是"用模型的人"，把别人预训练好的大模型，通过 `deeptutor/services/llm/` 这一层接进来。所以本章讲的预训练，你要理解，但不用会做。
- **DeepTutor 的价值在循环和上下文**。同样一个 GPT，套上不同的循环和上下文，能变成客服、变成程序员、变成老师。DeepTutor 做的就是"变成老师"这件事。
- **`UnifiedContext` 是"喂给模型的一切"的容器**。在 `deeptutor/core/context.py:34` 定义，它的注释直白地写着"Everything a capability or tool needs to process a single user turn"（一次用户回合里，能力或工具需要的全部东西）。第 5 章讲上下文工程时会回到它。

## 1.12 三个常见误解，现在澄清

**误解一：模型在回答时会去网上查资料。**
默认情况下不会。它只是在用训练时固化在参数里的"记忆"生成文字。要让它查资料，必须由程序显式给它一个搜索工具——这正是智能体框架要做的事。

**误解二：参数越多一定越好。**
不一定。对"总结这段话"这种简单任务，小模型又快又便宜，效果差别不大。DeepTutor 支持云端和本地两种 provider（`deeptutor/services/llm/cloud_provider.py` 与 `local_provider.py`），就是为了让你按任务难度选模型。

**误解三：模型记得我们之前聊过什么。**
模型本身**没有记忆**。每次调用都是全新的、失忆的。你之所以觉得它记得，是因为程序每次都把之前的对话记录重新拼进请求里发过去。上下文一旦满了，早期对话就得被裁掉——这就是第 5 章"上下文工程"要解决的核心难题。
